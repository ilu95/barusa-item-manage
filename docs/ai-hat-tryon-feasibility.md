# 모자 착용샷 AI 생성 시스템 — 기술 타당성 조사

조사 기준일: 2026-09-18 / 대상: 온라인 모자 전문점 (barusa)

---

## 0. 결론 요약

**가능합니다. 단, "어떤 착용샷이냐"에 따라 난이도와 리스크가 완전히 달라집니다.**

| 시나리오 | 오픈소스만으로 가능? | 품질 | 권장도 |
|---|---|---|---|
| A. 가상 모델(AI 사람)에게 자사 모자를 씌운 **상품 이미지 배치 생성** | 가능 | 상용 수준 | **1순위 — 즉시 착수** |
| B. 고객이 올린 셀피에 모자 합성 (비실시간, 10~60초) | 가능 | 편차 큼, 검수 필요 | 2순위 — 파일럿 |
| C. 정지 착용샷 → 3~5초 영상 클립 | 가능 | 불안정 (모자 형태 뒤틀림) | 3순위 — 실험 |
| D. 카메라 실시간 착용 (AR 미러) | **생성형 AI로는 불가** | — | AR(3D+페이스트래킹)로 별도 접근 |

핵심 판단 근거 3가지:
1. **라이선스가 해결됐다.** Qwen-Image-Edit 계열이 Apache 2.0으로 풀려 있어 상업적 사용에 로열티/추가 계약이 필요 없습니다. (FLUX 계열은 별도 상용 라이선스 구매 필요 — 주의)
2. **비용이 무시할 수준이다.** 상품 1개당 4컷 기준 생성 비용이 GPU 클라우드 기준 수십 원대입니다.
3. **모자는 의류 전용 Try-On 모델의 사각지대다.** 기존 VITON 계열(StableVITON/CatVTON 등)은 상·하의 학습 데이터로 훈련돼 모자에는 쓸 수 없습니다. → **범용 이미지 편집 모델 + 마스킹** 경로로 가야 합니다. 이게 이번 조사에서 가장 중요한 발견입니다.

## 1. 모델 선택

### 1-1. 이미지 (핵심 엔진)

| 모델 | 라이선스 | 상업적 사용 | 비고 |
|---|---|---|---|
| **Qwen-Image-Edit (2509 / 2511)** | **Apache 2.0** | **자유** | 20B MMDiT. 다중 이미지 입력(사람+상품) 지원, ControlNet(keypoint/sketch) 네이티브 지원 |
| Step1X-Edit v1.2 | Apache 2.0 | 자유 | 대안/앙상블용 |
| FLUX.1 Kontext [dev] | FLUX Non-Commercial | **불가 (유료 계약 필요)** | 품질은 좋으나 쇼핑몰 상업 이용 시 BFL 라이선스 구매 필수 |
| SDXL + IP-Adapter + Inpaint | 대부분 개방 | 자유 | 구식이지만 제어가 쉽고 VRAM이 적게 듦 |

→ **주력: Qwen-Image-Edit 최신판.** "person + product" 조합 편집을 명시적으로 지원하는 점이 우리 유스케이스와 정확히 일치합니다.

### 1-2. 의류 Try-On 전용 모델을 쓰지 않는 이유

StableVITON, CatVTON, Leffa 등 공개 VTON 모델은 VITON-HD/DressCode(상의·하의) 데이터로 학습돼 있어 **머리/모자 영역을 다루지 않습니다.** 최근 액세서리·장신구 Try-On 연구(ornaments VTON, 아웃핏 단위 데이터셋 등)가 나오고 있으나 대부분 논문 단계이고 모자 전용 사전학습 가중치는 사실상 없습니다.

→ 결론: **범용 편집 모델 + 머리 영역 마스크 + (필요 시) 자사 상품 LoRA** 구성이 현실적인 유일한 오픈소스 경로입니다.

### 1-3. 영상

| 모델 | 상태 | 로컬 요구사항 |
|---|---|---|
| **Wan 2.2 (I2V)** | Apache 2.0, 공개 가중치 확정 | 5B 버전은 소비자용 GPU 가능 |
| HunyuanVideo 1.5 | 공개 | RTX 4090 1장, FP8+오프로딩 시 ~14GB |
| LTX-2 계열 | 2026년 초 오픈소스화 / 커뮤니티 라이선스(매출 기준 무료 구간) | 4K·오디오 동시 생성 |
| Wan 2.5 이상 | **가중치 공개 여부 불확실** — 검증 필요 | — |

⚠️ 영상 모델 쪽은 SEO성 블로그에 잘못된 "오픈소스" 표기가 많습니다. **실제 착수 전 Hugging Face 원본 저장소의 LICENSE 파일을 직접 확인**해야 합니다. (본 조사 환경에서는 huggingface.co 접근이 차단돼 1차 확인을 못 했습니다.)

## 2. 파이프라인 설계 (시나리오 A 기준)

```
[상품 사진 1~3장]  ─┐
                    ├─→ 배경제거(BiRefNet/rembg) → 모자 정면/측면 정규화
[가상 모델 사진 N장]─┘         │
   (고정 모델셋 사전 생성)     │
         │                     ▼
         └─→ 얼굴/머리 파싱 → 마스크 생성 → Qwen-Image-Edit
             (SCHP / SAM 계열)    (헤어라인 위쪽만)   (person + product)
                                          │
                                          ▼
                        업스케일 → 자동 QA(CLIP 유사도/색상 ΔE) → 사람 검수 → 게시
```

**"고정 모델셋"이 핵심 아이디어입니다.** 실제 모델 섭외 없이 성별·연령·헤어스타일·얼굴형별로 가상 인물 10~20명을 미리 확정 생성해 두고, 신상품이 들어올 때마다 그 인물들에게 씌웁니다. 이렇게 하면:
- 브랜드 룩앤필이 일관됨
- 초상권 문제 없음
- 고객이 자기와 비슷한 얼굴형을 골라볼 수 있음 (모자는 얼굴형이 구매 결정의 핵심)

### 품질 관리 장치 (필수)
생성형 모델은 **상품 디테일을 임의로 바꿉니다.** 로고, 챙 길이, 색상, 스티치가 변형되면 그대로 허위광고가 됩니다. 따라서:
1. 마스크를 헤어라인 위로 제한해 얼굴은 건드리지 않음
2. 생성 후 원본 상품컷과 **색상 차이(ΔE)·로고 영역 유사도 자동 검사**, 임계치 초과 시 자동 리트라이
3. **게시 전 100% 사람 검수** (초기 3개월은 예외 없이)
4. 판매량 상위 상품은 자사 상품 LoRA를 소량 학습해 재현율을 올림

## 3. 비용 추산

GPU 클라우드 시세(2026년 기준, RunPod 등):
- RTX 4090: 커뮤니티 $0.34/h, 시큐어 $0.69/h
- A100 80GB: $1.39/h
- H100: $1.99~2.99/h

Qwen-Image-Edit 생성 속도는 H100 기준 편집 1건당 약 45초, LightX2V 등 가속 적용 시 수 초 단위까지 단축됩니다.

**배치 생성(시나리오 A) 예시 — 신상품 100종 × 4컷 = 400장**
- 4090 FP8, 장당 ~60초 + 재시도/업스케일 감안 → 약 8~12시간
- 비용: **약 $3~8 (1만 원 내외)**

**온디맨드(시나리오 B) 예시 — 고객 셀피 합성**
- 서버리스 A100 $2.72/활성시간 기준, 요청당 30초 → **건당 약 $0.023 (30원)**
- 월 1만 건이면 약 30만 원 + 대기시간 UX 설계 필요

→ **비용은 전혀 병목이 아닙니다.** 실제 병목은 ①검수 인력 시간 ②상품 디테일 재현율 ③법적 표시 의무입니다.

## 4. 법률·규제 (한국, 실제로 중요함)

### 4-1. AI 기본법 — AI 생성물 표시 의무
- **2026년 1월 22일 시행.** 1년 이상 계도기간 운영 중.
- 의무 주체는 "인공지능사업자"로, **AI를 이용해 제품·서비스를 제공하는 모든 사업자를 포함** → 우리 쇼핑몰도 대상입니다.
- 이미지의 경우 좌측/우측/중앙 하단에 가시적 워터마크 또는 로고 삽입. 다운로드·공유 기능이 있으면 **파일 자체에 표시**(메타데이터 포함)가 필요.
- 위반 시 **최대 3천만 원 이하 과태료.**
- → 설계 단계부터 워터마크와 C2PA/메타데이터 삽입을 파이프라인에 넣어야 합니다. 나중에 붙이면 전량 재생성입니다.

### 4-2. 표시·광고법 (부당광고)
AI 착용샷이 실제 제품과 **색상·핏·크기**가 다르게 보이면 부당광고가 될 수 있습니다. 대응:
- 실측 사이즈·소재 정보를 별도 표기
- "AI 생성 이미지로 실제 제품과 차이가 있을 수 있습니다" 고지
- 색상은 AI 이미지가 아닌 **실촬 상품컷을 기준**으로 제공

### 4-3. 개인정보 (시나리오 B를 할 경우에만)
- 얼굴 사진 자체는 원칙적으로 **민감정보가 아닌 일반 개인정보** → 수집·이용 동의 필요.
- 다만 얼굴에서 **특징정보(임베딩)를 생성**하면 생체인식정보로서 **민감정보**가 되어 별도 동의가 필요합니다. → 파이프라인에서 얼굴 임베딩을 저장하지 않도록 설계하면 리스크가 크게 줄어듭니다.
- 원본 사진은 생성 직후 즉시 삭제, 보관기간·목적 명시.

## 5. 기술적 난관 (솔직한 평가)

1. **헤어 오클루전.** 모자가 머리카락을 누르는 자연스러움이 가장 어렵습니다. 긴 머리·볼륨 헤어일수록 실패율이 높음 → 고정 모델셋을 짧은/묶은 머리 위주로 구성해 회피.
2. **상품 동일성.** 범용 편집 모델은 "비슷한 모자"를 그리지 브랜드 제품을 정확히 복제하지 않습니다. 자수 로고·라벨은 특히 취약 → LoRA + 자동 QA + 사람 검수로만 관리 가능.
3. **머리 크기/비율.** 모자 사이즈감(오버핏/딥크라운)이 이미지에서 왜곡되면 반품률이 올라갑니다. → 사이즈는 이미지가 아닌 수치로 커뮤니케이션.
4. **영상.** I2V는 모자 실루엣이 프레임 간에 흔들리는 경우가 흔합니다. 3초 이하, 미세한 움직임(약한 카메라 무빙/머리 소폭 회전)으로 제한할 것.
5. **실시간 미러**는 생성형 모델로 불가능합니다(초당 수십 프레임 불가). 필요하면 MediaPipe 페이스메시 + 3D 모자 에셋 기반 AR로 완전히 다른 스택을 써야 합니다.

## 6. 권장 로드맵

**1단계 — PoC (1~2주)**
Qwen-Image-Edit + ComfyUI로 자사 모자 5종 × 가상 모델 3명 = 15컷 수동 생성. 재현율/실패 유형 측정. **여기서 "쓸 만한지" 판단이 갈립니다.**

**2단계 — 배치 파이프라인 (3~4주)**
고정 모델셋 확정(10~20명) → 배경제거·마스킹·생성·업스케일·워터마크 자동화 → 상품관리 시스템과 연동, 검수 큐 UI 구축.

**3단계 — 확장 (선택)**
- 판매 상위 상품 LoRA 학습
- 3초 영상 클립 (Wan 2.2 I2V)
- 고객 셀피 업로드 (법적 검토 완료 후)

**PoC 없이 전면 도입은 권하지 않습니다.** 상품 재현율은 실제 자사 모자 사진으로 돌려보기 전에는 예측할 수 없습니다.
