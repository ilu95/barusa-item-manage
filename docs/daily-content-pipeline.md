# 가상 모델 기반 데일리 콘텐츠 생성 시스템 — 설계안

확정 범위: 고객 셀피 합성 없음. **자사 전속 AI 모델을 고정 자산으로 만들어 두고, 거기에 모자를 씌워 매일 콘텐츠를 생산한다.**

작성일: 2026-09-18

---

## 0. 범위가 좁혀지면서 사라진 문제 / 새로 생긴 문제

### 사라진 것 (좋은 소식)
- **개인정보 이슈 전면 소멸.** 고객 얼굴을 받지 않으므로 생체정보·동의·파기 정책이 전부 불필요.
- **실시간 성능 요구 소멸.** 야간 배치로 돌리면 되므로 GPU 1장이면 충분. 지연시간 UX 설계 불필요.
- **입력 품질 편차 소멸.** 조명·각도·해상도가 제각각인 셀피를 다룰 필요가 없음. 우리가 통제하는 이미지만 다룸.
- **실패 시 리스크 소멸.** 결과가 이상하면 그냥 버리면 됨. 고객이 대기 중인 상황이 아님.

→ 기술 난이도가 체감상 **1/3 수준으로 떨어집니다.**

### 새로 생긴 것 (진짜 난제)
1. **캐릭터 일관성** — 어제의 "지민"과 오늘의 "지민"이 같은 사람으로 보여야 합니다. 이게 1순위 기술 과제입니다.
2. **콘텐츠 다양성** — 같은 모델·같은 구도가 반복되면 계정이 죽습니다. 매일 돌리는 시스템의 진짜 수명은 여기서 갈립니다.
3. **가상인물 표시 의무** — 2026년 6월 1일부터 이미 시행 중. 아래 4장 참조. **이 방식에 직격으로 적용됩니다.**

## 1. 캐릭터 일관성 — 해결 방법

### 접근: 전속 모델 1명 = LoRA 1개

```
1) 시드 인물 확정
   Qwen-Image로 얼굴형/헤어/분위기별 후보 생성 → 마음에 드는 1장 선택

2) 데이터셋 자동 확장
   Qwen-Image-Edit로 그 1장을 각도·표정·조명·의상 변형 → 20~30장
   (Qwen-Image-Edit는 정체성을 유지한 채 변형하는 게 강점이라
    이 용도로 쓰기 좋습니다. 사람 모델 섭외 없이 데이터셋이 나옴)

3) 캐릭터 LoRA 학습
   musubi-tuner / ai-toolkit, 이미지 20~30장
   RTX 4090 기준 수 시간. 1회만 하면 영구 자산

4) 모델 카드로 고정
   { LoRA 파일, 레퍼런스 이미지 5장, 고정 프롬프트, 시드,
     키·얼굴형·헤어 설정, 금지 표현 } → DB 저장
```

이후 매일의 생성은 **"모델 카드 + 모자 + 씬"** 3개 조합을 불러오는 것으로 끝납니다.

전속 모델은 **6~10명**을 권장합니다. 20명은 관리가 안 되고, 3명은 금방 질립니다. 구성 예:
- 얼굴형 축: 둥근형 / 각진형 / 긴형 (모자 구매의 핵심 관심사)
- 성별·연령 축: 20대 여 2, 20대 남 2, 30대 여 1, 30대 남 1
- 헤어 축: 짧은머리 위주 (긴 생머리는 모자 합성 실패율이 높음 — 2명 이하로)

### 실패 모드 관리
| 증상 | 원인 | 대응 |
|---|---|---|
| 날마다 얼굴이 미묘하게 다름 | LoRA 강도 부족 / 프롬프트 흔들림 | LoRA weight 고정, 프롬프트를 모델 카드에서만 로드 |
| 특정 각도에서 얼굴 붕괴 | 데이터셋 각도 편중 | 데이터셋에 측면·하이앵글 보강 후 재학습 |
| 모자 씌우면 얼굴까지 바뀜 | 마스크 범위 과다 | 마스크를 헤어라인 위로 제한 |

## 2. 시스템 구조

```
┌─ 자산 레이어 (한 번 만들고 계속 씀) ─────────────┐
│  모델 레지스트리   : 6~10명 × {LoRA, 레퍼런스, 프롬프트카드}
│  상품 레지스트리   : 모자별 {정면/측면/디테일컷, 누끼,
│                              기준색 Lab값, 사이즈 실측}
│  씬 라이브러리     : 배경 × 조명 × 구도 × 계절 조합 풀
└──────────────────────────────────────────────────┘
                      │
┌─ 기획 레이어 (매일 자동) ────────────────────────┐
│  콘텐츠 캘린더 → 오늘의 조합 N개 샘플링
│  (최근 30일 사용 조합 제외 → 중복 회피)
└──────────────────────────────────────────────────┘
                      │
┌─ 생성 레이어 (야간 배치, GPU) ───────────────────┐
│  ComfyUI API 모드 + 작업 큐
│  Qwen-Image-Edit + 캐릭터 LoRA + 머리 마스크
│  → 업스케일 → 자동 QA → 표시/워터마크 삽입
└──────────────────────────────────────────────────┘
                      │
┌─ 검수·발행 레이어 (사람, 아침 10분) ─────────────┐
│  후보 20~30장 → 사람이 5~8장 승인 → 예약 발행
└──────────────────────────────────────────────────┘
```

### 자동 QA (사람 검수 전에 불량 걸러내기)
- 상품 색상: 생성물의 모자 영역 평균색 vs 기준 Lab값 → ΔE 임계 초과 시 폐기
- 상품 형태: 원본 누끼와 IoU / CLIP 유사도
- 얼굴 동일성: 모델 레퍼런스와 face embedding 코사인 유사도 (내부 QA 용도로만 사용, 저장 금지)
- 해부학 오류: 손가락 개수 등은 아직 자동 검출이 약함 → 사람 검수에 의존

이 자동 QA가 있어야 **아침 검수 시간이 10분으로 유지**됩니다. 없으면 30장 전부 눈으로 봐야 하고, 두 달 안에 운영이 멈춥니다.

## 3. 콘텐츠 유형 (다양성 확보가 시스템 수명을 결정)

매일 같은 "모델이 모자 쓴 사진"만 올리면 3주면 소진됩니다. 템플릿을 유형화해 두고 캘린더가 순환시켜야 합니다.

| 유형 | 내용 | 비중 |
|---|---|---|
| 신상 착용컷 | 입고 상품 기본 3컷 (정면/측면/디테일) | 입고 시 |
| 얼굴형별 추천 | 같은 모자를 얼굴형 다른 모델 3명이 착용 비교 | 주 2회 |
| 컬러 비교 | 같은 모델, 같은 구도, 색상만 변경 | 주 1회 |
| 데일리 코디 | 계절/날씨/상황(출근·여행·운동)별 스타일링 | 주 2회 |
| 스타일링 팁 | 챙 각도, 깊이 조절 등 정보성 | 주 1회 |
| 시즌·이벤트 | 장마/한파/벚꽃/휴가 등 시의성 | 수시 |

**"얼굴형별 추천"이 모자 카테고리의 킬러 콘텐츠입니다.** 전속 모델을 얼굴형 축으로 구성하라고 한 이유가 이것이고, 이건 실제 사람 모델로는 비용상 불가능한 콘텐츠입니다. 여기가 이 시스템의 진짜 경쟁력입니다.

## 4. 법적 요건 — **두 개의 별개 의무** (둘 다 이미 시행 중)

### 4-1. 공정위 「추천·보증 등에 관한 표시·광고 심사지침」 — 가상인물 표시
**2026년 6월 1일 시행. 이미 적용 중입니다.**

- 대상: "인공지능 등을 기반으로 실제와 구분하기 어려운 가상의 인물" → **우리 전속 AI 모델이 정확히 여기 해당**
- 표시 방법:
  - **문자 중심 매체**(블로그, 카페 등): 제목 또는 첫 부분에 `AI를 기반으로 생성된 가상인물이 포함된 게시물입니다` 또는 `가상인물 포함`
  - **사진·동영상**: 가상인물이 등장하는 **동안 내내, 인물과 가까운 위치**에 `가상인물` 문구 노출
- 위반 시: 기만적 표시·광고 → 시정명령·과징금·형사처벌 대상
- 적용 제외 가능성: 명백한 만화·일러스트 캐릭터, 라이선스 보유한 실존인물 기반 디지털휴먼, 단순 보정·합성

**⚠️ 가장 중요한 실무 함정:** 지침은 "가상인물임을 표시했더라도 **그 가상인물이 하는 광고 내용이 실제 경험적 사실에 부합하지 않으면** 여전히 부당광고"라고 명시합니다.
→ 즉 **AI 모델이 "써보니 진짜 가볍고 좋아요" 같은 체험 증언을 하면 안 됩니다.** 카피 톤을 반드시 *체험 증언형*이 아니라 *제품 소개형*으로 잡아야 합니다. 이건 프롬프트/카피 템플릿 설계 단계에서 못 박아야 하는 사항입니다.

### 4-2. AI 기본법 — AI 생성물 표시
**2026년 1월 22일 시행 (1년 이상 계도기간 운영 중).**
- AI를 이용해 제품·서비스를 제공하는 사업자 전반이 대상
- 이미지 하단(좌/우/중앙)에 가시적 워터마크 또는 로고
- 외부 다운로드·공유 기능이 있으면 파일 자체(메타데이터 포함)에 표시
- 위반 시 최대 3천만 원 이하 과태료

### 4-3. 설계 반영 사항
1. 이미지 생성 시 **하단에 표시 영역을 미리 비워서 구도를 잡을 것.** 나중에 덧붙이면 인물이 가려지거나 재생성이 필요합니다.
2. `가상인물` 문구는 **인물 근처**, AI 생성 워터마크는 **하단** — 위치 요건이 달라 두 개를 따로 넣어야 합니다.
3. 영상 콘텐츠는 **등장 구간 내내** 문구가 유지돼야 하므로 오버레이를 전체 구간에 적용.
4. 카피 생성 템플릿에 체험 증언형 표현 **금지어 리스트**를 하드코딩.
5. 실제 색상·사이즈는 AI 이미지가 아닌 **실촬 상품컷·실측 수치**로 별도 제공 (표시광고법 부당광고 방지).

## 5. 비용

하루 30장 생성 기준 (재시도 포함 실효 50장):
- RTX 4090 FP8, 장당 ~60초 → 약 1시간
- 커뮤니티 클라우드 $0.34/h → **하루 약 500원, 월 1.5만 원**
- LoRA 학습은 모델당 1회, 수 시간 → 6명이면 초기 1~2만 원

로컬에 RTX 4090/5090급 1장을 두면 클라우드 비용조차 0입니다. 매일 돌리는 워크로드라면 **6개월이면 GPU 구입비가 회수**됩니다.

→ **운영 비용은 사실상 무의미한 수준. 실제 비용은 아침 검수 10분 × 매일입니다.**

## 6. 구축 순서

| 단계 | 기간 | 산출물 | 성공 기준 |
|---|---|---|---|
| 1. 모델 1명 PoC | 1주 | 전속 모델 1명 LoRA + 착용컷 20장 | 같은 사람으로 보이는가 / 모자 재현되는가 |
| 2. 모델셋 구축 | 1~2주 | 6~10명 LoRA + 모델 카드 DB | 얼굴형 축 커버 완료 |
| 3. 배치 파이프라인 | 2~3주 | ComfyUI API + 큐 + 자동 QA + 표시 삽입 | 야간 무인 실행, 아침 후보 30장 |
| 4. 기획·검수 UI | 1~2주 | 콘텐츠 캘린더 + 검수 큐 화면 | 아침 검수 10분 내 |
| 5. 발행 연동 | 1주 | SNS 예약 발행 | 무인 운영 진입 |

**1단계에서 판단이 갈립니다.** 전속 모델 1명을 만들어 실제 자사 모자 3종을 씌워보면, 이 시스템을 끝까지 갈지 여부가 바로 나옵니다. 여기까지가 1주입니다.
